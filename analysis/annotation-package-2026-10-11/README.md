# CoSMiT 行为保持与测试意图保持标注包

请先阅读本文件，再填写 **[ANNOTATIONS.md](ANNOTATIONS.md)**。共 110 个候选：原批次 80 个、扩充批次 30 个；D0028 和受控变体不在表内。

## 标注对象与两个定义

**行为保持**：在明确的输入范围与比较规则下，迁移前后 API 的操作行为保持一致，例如返回值、形状、类型或异常。声明的比较维度需由标注者核查，不能以 API 名称相似作为依据。

**测试意图保持**：源测试原本要检验的目标或性质，在迁移后的测试中仍得到检验。请先写明源测试意图，再检查相关断言、预期异常、输入构造、数据流及适配逻辑。

两列分别判断，不预设包含关系：

| 行为 | 意图 | 抽象示例（不是本数据集的预置答案） |
| --- | --- | --- |
| 保持 | 保持 | API 行为一致，原检查目标也保留 |
| 保持 | 不保持 | API 行为一致，但迁移删除了关键检查 |
| 不保持 | 保持 | 目标行为有差异，保留的原检查正确报告失败 |
| 不保持 | 不保持 | 操作行为与测试检查目标都发生变化 |

测试失败本身不等于意图丢失。测试通过本身也不等于意图保持。

## 建议填写流程

1. 每位标注者复制一份包，在表中填写姓名或编号。首次独立标注时不要查看其他人的标签或已有方法输出。
2. 打开候选材料页，先看源码、来源、输入范围和框架版本。检查源端是否适用；源端无效的输入不能自动成为迁移反例。
3. 独立填写行为标签与依据。原始观察覆盖所有登记输入及三次重复，没有只选出差异输入；它们是可检查的观察，不是预设标签。
4. 如果有测试对，阅读测试正文、注册信息、输入范围和共享适配代码，先描述源测试意图，再填写意图标签。不要直接使用操作契约替代源测试意图。
5. 两个结论分别写证据：代码文件与行号、input_index/repeat、规格出处或自己的复核记录。包内未包含现成的方法判断、模型回答、反例清单或建议标签。
6. 把最终结论回填主表。若有第二位标注者，先各自填写再讨论分歧；原标签与讨论后的标签分别保留，不能用方法输出裁决分歧。

## 标签规则

- **待标注**：尚未工作，初始占位值。
- **保持**：在写明的范围内，有足够证据支持对应性质保持。不能仅凭有限观察对无限输入域作结论。
- **不保持**：存在范围内有效反例，或者有可核查的测试检查目标丢失／改变证据。必须给出依据。
- **证据不足**：缺少配对测试、必要环境、源意图依据，或目前证据无法判断。不能按负例或正例统计。
- **不适用**：该评估对象或范围确实不适用；必须说明原因。仅因文件缺失、运行失败或暂时无法确认，不应随意使用此标签。

默认行为标注范围是登记输入和声明的比较规则。如果要标注更广的输入域，请明确扩大后的范围及证明／复核依据。混合有效和无效输入时分别记录，不能简单给整组赋无效标签。

## 每个候选有什么

- `README.md`：材料入口、局限及详细标注记录模板。
- `source-operation.py` / `target-operation.py`：迁移前后操作函数，原文保留。
- `metadata.json`：函数入口、框架、公开 counterpart 来源和代码哈希。
- `inputs.json`：64 个登记输入，以 input_index 对齐。
- `declared-behavior-scope.json`：声明的行为范围、条款和容差；不是 gold。
- `observations.json`：三次重复的源／目标原始观察。`not-executed` 表示没有执行记录，不是自动判定目标错误。
- `source-api-documentation.txt` 或 `source-specification-links.json`：已有源规格摘录或引用。若包内只有链接，需要另行查阅对应版本，不能把未核实链接当作已复核证据。

**27 组有构造测试对**：另外附源／目标测试、方法入口、测试参数、上游全文和共享执行适配上下文。这些测试是操作替换构造的，源目标共用源框架断言环境；不是历史迁移测试。返回值桥接会影响原生类型、布局、别名或容器义务，需要标注者检查。

**83 组没有已配对的完整测试正文**：仍可独立评估行为，但不能仅凭函数代码证明完整测试意图保持。有些材料页附源测试检索线索；这些只是语法引用，未确认与候选配对，也可能只把 API 当作辅助操作。

对于二元操作构造测试，源／目标正文可能相同，实际被调用的函数由执行环境注入；必须结合 `test-registration.json` 和共享 runner 理解，不能据文本相同直接给意图标签。

## 代码运行与环境

直接阅读材料不需要安装深度学习框架。
操作函数可通过 `tools/replay_operation.py` 按单个输入复核；运行需要自行准备 Python、NumPy 及对应的 PyTorch/TensorFlow。脚本不会安装依赖或调用模型。

```powershell
python tools/replay_operation.py --case D0001 --side source --input-index 0
python tools/replay_operation.py --case D0001 --side target --input-index 0
```

脚本只输出所选操作的执行观察，不自动给出行为或意图标签。它不复现完整测试 harness、目标绑定插桩或所有扰动实验。测试正文中的 Harness、_operation 和内部框架工具需参照 `shared/retained-runner-context.txt`；这个只读上下文保留原路径，不能直接当作独立运行入口。

原始观察逐条记录了框架版本：主要使用 TensorFlow 2.20.0、PyTorch 2.9.1（部分记录带 +cpu）；原始批次 NumPy 2.1.3，扩充动态批次 NumPy 2.4.6。复核使用不同环境时需记录差异，不要混称为原环境重放。

## 完整性与交付

`SHA256.json` 校验所有初始包内文件；修改标注文件后相应哈希变化属于正常情况，保留原包即可。
标注完成后至少返回 ANNOTATIONS.md 和修改过的候选 README；新增复核代码／记录请放在候选目录下的 `reviewer-evidence/`，并在表格中引用。
此包没有预置人工正确答案。材料来自已有、经过开发审阅的数据，并不能据此声称整个实验已经盲化或样本独立。
